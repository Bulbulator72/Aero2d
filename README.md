# aero2d — аэродинамика двумерных профилей

Прототип этапов 0–2 дорожной карты: эталонные тесты, быстрый панельный метод
и пакетный решатель уравнений Эйлера на JAX (CPU/GPU, FP32/FP64).

## Состав

| Модуль | Что делает | Состояние |
|---|---|---|
| `aero2d/geometry.py` | NACA 4, CST (Кульфан), профили Кармана–Треффца/Жуковского с **точным** решением, чтение файлов Selig | готово |
| `aero2d/panel.py` | Панельный метод в формулировке через функцию тока (как XFOIL): линейная завихренность, условие Кутта, экстраполяция на острой кромке; поправка Кармана–Цяня | готово, **2-й порядок**, проверен по точным решениям |
| `aero2d/grid.py` | O-сетка: маршевый рост слоёв по сглаженным нормалям, геометрическое нарастание шага | готово (для Эйлера) |
| `aero2d/euler.py` | Уравнения Эйлера: конечные объёмы, HLLC, MUSCL + ван Албада, характеристическое условие на внешней границе с поправкой на вихрь; явная схема RK4 + сглаживание невязки | готово; явная схема — запасной вариант |
| `aero2d/implicit.py` | **Основной решатель**: псевдонестационарный Ньютон–Крылов (GMRES), точный якобиан через `jax.jvp`, предобусловливатель — блочная прогонка вдоль нормали к стенке; пакет случаев через `jax.vmap` | готово |
| `aero2d/core.py`, `aero2d/gui.py` | Окно программы (`python -m aero2d.gui`): профиль NACA или из файла, поляры панелями или Эйлером, графики Cl/Cd/Cm/Cp, таблица, экспорт CSV/PNG | готово |
| `tests/` | pytest: точные решения, консервативность, сходимость | |
| `benchmarks/` | эталонный набор и тест пропускной способности GPU | |

## Установка

На Windows рекомендуется WSL2 (Ubuntu): JAX с CUDA работает только под Linux.

```bash
pip install -e ".[test]"          # CPU
pip install -U "jax[cuda12]"      # GPU (RTX 3080 Ti), в WSL2 или Linux
pytest -q
```

## Быстрый старт

```python
from aero2d.geometry import naca4
from aero2d.panel import PanelSolver
from aero2d.grid import ogrid
from aero2d.euler import EulerSolver
from aero2d.implicit import ImplicitEuler

af = naca4("2412", 121)

# панели: поляра за миллисекунды
ps = PanelSolver(af)
print(ps.solve(4.0, mach=0.5).cl)

# Эйлер: весь пакет (M, α) решается одновременно
g = ogrid(af, nj=65)
solver = ImplicitEuler(EulerSolver(g))          # dtype=jnp.float32 по умолчанию
r = solver.solve(machs=[0.5, 0.7, 0.8], alphas=[2, 2, 1.25], n_iter=100)
print(r.cl, r.cd, r.cm, r.converged)
```

## Проверено

* **Панельный метод**: ошибка Cl относительно точного решения 0,02 % при 160 панелях,
  второй порядок сходимости (в 4 раза при удвоении), включая профили с «клювом».
  Первоначальная формулировка через скорости давала только первый порядок
  (0,6 %) — заменена.
* **Эйлер** (грубая сетка 128×49): при M = 0,5, α = 2° Cl = 0,2816 — между
  поправками Прандтля–Глауэрта (0,279) и Кармана–Цяня (0,292), Cd ≈ 0;
  NACA 0012 при M = 0,8, α = 1,25° — Cl = 0,349, Cd = 0,0220
  (эталон Cl = 0,351, Cd = 0,0227); M = 0,85, α = 1° — Cl ≈ 0,34, Cd ≈ 0,056.
* **Неявный решатель**: дозвук и M = 0,8 сходятся за 20–50 итераций Ньютона;
  при M = 0,85 за 80 итераций невязка падает на 4 порядка (силы уже стабильны).
* **FP32 и FP64** дают одинаковые Cl, Cd, Cm (расхождение ≤ 2·10⁻⁴). Разница —
  в «полу» невязки: FP32 останавливается на ~10⁻⁶ от начальной, FP64 идёт до
  10⁻¹³. Для сил этого достаточно; для RANS при y⁺ ~ 1 и Re до 10⁸ нужно
  проверить отдельно.

Подробные цифры — `benchmarks/results.md` (после запуска `run_benchmarks.py`).

## Известные ограничения

* Задняя кромка должна быть замкнутой (`close_trailing_edge()` для остальных).
* Маршевый генератор O-сетки выворачивает ячейки, если первый шаг от стенки
  намного меньше шага по контуру (например, 33 точки на сторону при ds0 = 10⁻³).
  Для Эйлера это не мешает, для RANS понадобится отдельный (эллиптический или
  C-сеточный) генератор.
* Многосеточный ускоритель явной схемы (`mg_levels > 1`) неустойчив при M < 0,6 —
  экспериментальный, по умолчанию выключен. Основной путь — неявный решатель.
* В трансзвуке с сильными скачками (M ≥ 0,85) нужен умеренный `cfl_max` (~300):
  при больших шагах Ньютон может «застрять» на нефизичном положении скачков.
* При M < 0,3 нужно предобусловливание для малых чисел Маха (следующий этап).
* Сверхзвук (M > 1) пока не проверялся; граничное условие его поддерживает.
* Вязкости нет: пограничный слой и RANS — следующие этапы.

## Следующие шаги

1. Запустить `benchmarks/gpu_throughput.py` на RTX 3080 Ti (FP32 и `--fp64`) —
   это главный ответ на вопрос о жизнеспособности GPU-подхода.
2. Предобусловливание для малых M, проверка сверхзвука (ромбовидный профиль,
   метод скачков и волн разрежения).
3. Вязко-невязкий метод (панели + интегральный пограничный слой, eᴺ).
4. RANS (SA, затем SST и γ-Reθ) на основе того же неявного ядра.
